Velox modules are persisted, reusable configuration objects. Connections, Definitions, Maps, Reports, Transports, SQL Scripts, Scriptlets, Variable Groups, APIs and Flows can be related and shared; changing one module can therefore affect multiple integrations.

- Use the [module catalogue](module-catalogue.md) to choose the correct object type.
- Review [common module properties](common-module-properties.md) before editing a concrete type.
- Use [folders, naming and organisation](folders-naming-and-organisation.md) to keep the tree navigable without confusing folders with runtime isolation.
- Follow [module lifecycle actions](lifecycle-actions.md) for creation, cloning, enabling, archiving and deletion.

Always use **Check Usage** or relation/dependency evidence before changing a shared module.
